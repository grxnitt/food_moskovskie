# Развёртывание на Vercel

## Причина исходной ошибки

Vercel определял репозиторий как Next.js, однако `npm run build` запускал Vinext и создавал Worker в `dist/server`. Поэтому Vercel не находил `.next/routes-manifest.json`. Простая смена Output Directory не решала бы проблему: код базы использует нативную привязку Cloudflare D1.

## Два целевых окружения

- `npm run build` / `dev` / `start`: стандартный Next.js для Vercel и локального Node.js. Сборка создаёт `.next` и динамические API-функции.
- `npm run build:sites` / `dev:sites` / `start:sites`: исходный Vinext/Cloudflare Worker с нативным D1.

`lib/runtime.ts` экспортирует окружение Cloudflare. Конфигурация Next.js заменяет его на `lib/runtime.node.ts`, чтобы `cloudflare:workers` не попадал в Node.js Functions. Обработчики обёрнуты в `withBackend`: при наличии нативного D1 выполняют прежний код, иначе используют серверный HTTP-прокси.

## Серверное подключение

В проекте Vercel `food_moskovskie` настроены:

- `PEREMENA_BACKEND_URL`: адрес существующего закрытого сервиса Sites.
- `PEREMENA_BACKEND_TOKEN`: секрет служебного доступа только для сервера, в sensitive-переменной production/preview.

Ключ не хранится в репозитории или клиентском коде. API не возвращает фиктивные данные при отсутствии настроек, а отвечает 503. База остаётся в D1: перезапуск, масштабирование или новый деплой Vercel не удаляют записи.

Прокси допускает только пять известных API-путей и их методы. Для записи проверяет Origin относительно HTTP Host, ограничивает размер тела и передаёт запрос в закрытый backend с серверной авторизацией. Переадресации не выполняются. Cookie авторизации Vercel и входящие заголовки `oai-authenticated-user-*` не передаются: в backend отправляется только собственная `peremena_session`.

На Vercel сессия браузера определяет избранное и право редактировать отзыв. Это отдельная сессия от входа через ChatGPT на исходном сайте Sites. Общий каталог и опубликованные отзывы используют прежнюю D1. Защита самого Vercel-сайта остаётся настройкой Vercel Authentication.

## Локальная проверка

Создайте `.env.local` по образцу `.env.example`. Заполните служебный ключ локально, не отправляя его в чат и не добавляя в Git. Затем:

```sh
npm ci
npm run build
npm start
```

Во втором терминале:

```sh
npm test
```

Тесты обращаются к реальной базе через сервер. Они создают только собственные проверочные отзывы и избранное и затем удаляют их. Проверка рейтингов учитывает существующие отзывы других пользователей.

## Настройки проекта

`vercel.json` фиксирует framework `nextjs`, Install Command `npm ci`, Build Command `npm run build` и Output Directory `.next`. Git-ветка production — `main`. Не указывайте для этого целевого окружения `dist`, `dist/server` или `build:sites`.
